## 1. 总体状态

当前小程序的内容浏览主链路已在微信开发者工具中跑通，默认使用本地 Mock/内联数据。
登录、用户资产、UGC、埋点、TTS 和完整题库/私有素材地址已接入 CloudBase，
因此项目不能再概括为“完全不依赖后端”，也不能把本地通过等同于已上线。

核心状态与成果：
- **休闲模式**：已全面覆盖香、音、茶、影、养、游六雅板块，实现高水准的生活美学界面与数据关联。
- **学习模式**：已实现教程、知识、面试、复习四大模块。
- **数据解耦**：服务层已完成 mock/API 切换边界重构，页面不直接读 mock。
- **面试题库**：已扩展至 18 个技术栈专题文件。本地精简版 **90 道**（每专题5题），完整数据集 **901 道**（存放在 `data/study_data.json` 供云端部署）。
- **账号级本地数据隔离**：对仍使用历史全局 Storage 键的收藏、签到、浏览/搜索历史、
  积分徽章、偏好、通知、学习进度/错题、笔记、播放进度和订阅状态，登录切换时
  保存为 `account_snapshot:<users._id>` 并清空活动键；云端确认身份后只恢复当前账号。
  未知旧数据隔离，登录失败保持清空。
- **登录/签到并发保护**：`login` 对新账号使用 OPENID 摘要确定性用户 ID；
  `sign` 对 `OPENID + 北京日期` 使用确定性签到 ID。两者原子新增，同日重复签到
  返回 `alreadySigned`，客户端只对首次成功增加积分。
- **UGC 本地实现**：公开投稿进入 `pending`，只有人工设为 `approved`
  才进入社区；本地缓存按云端确认账号隔离。删除失败保留 `deleting` 重试数据，
  删除成功保留客户端过滤的最小 `deleted` 墓碑，防止离线副本复活；多设备旧 dirty
  副本进入账号级冲突隔离区，不会自动覆盖云端。
- **UGC 外部边界**：最新云函数部署、历史数据迁移、人工审核/清理演练和
  第二真实账号验收均未确认完成。

## 3. 架构设计与数据流向

### 3.1 休闲 & 学习双模式架构
系统采用“双模式”动态切换机制，通过全局 `store/index.js` 统一管理状态：
- **休闲模式 (Leisure)**：展示六雅宫格入口、每日风雅推荐、综合内容流，侧重美学生活。
- **学习模式 (Study)**：展示待掌握/已掌握统计、今日复习卡片、技术栈宫格，侧重知识积累。

### 3.2 数据流向分层设计
为方便未来快速接入真实服务端 API，项目在服务层与数据源间建立了严格的切换边界：
```text
[视图层 Pages]
      │
      ▼
[服务层 services/*] (例如 tea.js, travel.js)
      │
      ▼
[网络与请求层 utils/request.js]
      │
      ├── (当 enableMock == false) ──► [真实 API 接口]
      │
      └── (当 enableMock == true)  ──► [Mock 适配层 utils/mock.js] ──► [内联数据源 utils/data-store.js]
```
